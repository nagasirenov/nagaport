# Correction to the initial CP58 sound candidate

The original production patch had one real malformed consumer transformation at XFactoryAccelerator.java147. It produced `ctx.getPlayer().com.hbm.sound.WorldSoundEffects.play(world, ...)` instead of `com.hbm.sound.WorldSoundEffects.play(ctx.getPlayer().world, ...)`.

The receiver regex accepted identifier/member suffixes but did not parse invocation expressions. It started at world after the closing parenthesis, leaving ctx.getPlayer(). before the fully qualified helper. The initial inverse checker repeated that same selector. Its70 controls proved consistency with its manifest, not correctness of the receiver range. The original helper runtime tests remain evidence for the helper itself, not for this malformed consumer or initial whole-port acceptance.

Correction: only that one production line changes. A separate full-source javac AST/type auditor identifies each selected MethodInvocationTree by manifest file/line, obtains the complete MemberSelectTree expression and UTF16 source ranges, performs JavacTask.analyze, and verifies actual receiver/first-argument types plus the final executable owner and overload. All96 original receivers are DECLARED native World; all96 corrected first arguments are World; all96 corrected calls resolve WorldSoundEffects.play(World,double,double,double,String,float,float). Six original argument expressions and types are preserved. The other95 initial transformations were correct.
