# Container native click and EMPTY boundary

Production ownership: `ContainerNT.java` and `ContainerBase.java` only. Original checkpoint bytes are recorded in `container-clicks-manifest.json`; temporary originals were captured in `/tmp/containers-before` before editing. This is a native API/representation port, not a replacement with vanilla's newer click algorithm.

## Semantic audit

- Old integer modes map explicitly to `PICKUP` (0), `QUICK_MOVE` (1), `SWAP` (2), `CLONE` (3), `THROW` (4), `QUICK_CRAFT` (5), and `PICKUP_ALL` (6). No ordinal mapping, fallback no-op implementation, or dropped old branch.
- Every Slot, player cursor and hotbar stack read used by the custom algorithm is normalized through `nativeStack`, preserving the live identity of nonempty stacks. Removal and transfer results are normalized before use. Native result/clear values are `ItemStack.EMPTY`; no stack-size mutation is performed on EMPTY. Slot callback is native `onTake`; drop method is native `dropItem`.
- Native Container drag state is private. The custom algorithm now owns equivalent drag fields/reset. Static native helpers provide event/mode extraction, placement eligibility and distribution. Drag modes 0/1 retain original comparisons/distribution. Mode 2 is explicitly rejected for both survival and creative players, preserving the original supported mechanics rather than adopting native 1.12 creative fill. Official 1.7.10 binary verification: Forge 1614 conf/packaged.srg maps zs/d(I)Z to Container.func_94528_d(I)Z; javap confirms true only for 0 or 1. The initial native-mode-2 extension was removed before the final common validation. The first non-drag click during active drag still only resets drag.
- Actual cached Forge 1.12.2 14.23.5.2768 / stable_39 `Container.slotClick` bytecode was inspected with javap. It accepts SWAP buttons 0..8, not offhand index 40. This port intentionally matches that version rather than silently adding later Minecraft GUI offhand behavior. All seven enum values have explicit branches.
- Removed `retrySlotClick` maps to the original recursive `slotClick(...QUICK_MOVE...)` operation. Its item-identity retry condition and first-return snapshot remain, rather than adopting vanilla's newer iteration or changing retry policy.
- Preserved anomalies: foreign-inventory hotbar exchange rehomes the previous hotbar stack into the first free player slot instead of placing it into the clicked inventory; take-only cursor merge increments cursor before removal and invokes onTake with cursor; collect-all adds requested removal count and tests the removed result for clear; base merge uses the inventory/max-item limit rather than per-slot limit; slot changed/callback ordering, copied-versus-live ownership and recursive shift semantics remain. No balancing/recipe/filter behavior changed.
- Existing other container classes with old integer slotClick overrides, other Slot callback overrides and separate transfer methods remain outside this two-file scope. This does not claim the whole container hierarchy compiles.

## Reproduction and exact scope

`testPortContainerClicks` is defined in `porting/container-clicks-probe.init.gradle`; parent owns shared Gradle execution. The Python probe also accepts `--java-home` and `--classpath` for standalone javac/java runs.

The probe compiles the **complete unmodified production ContainerNT source**, the exact production InventoryUtil Slot merge method and ItemStackUtil.carefulCopyWithSize method, and the exact ContainerBase constructor/canInteract/transfer/merge methods. ContainerBase's unrelated slot-construction helpers are omitted because their achievement/output-slot dependencies still have separate API debt. No Minecraft/Forge class is faked; native Bootstrap, ItemStack, Slot, InventoryBasic, InventoryPlayer, Container, ClickType and real World/EntityPlayer subclasses are used. Controlled player drop and Slot callback overrides measure effects without spawning a live server or world.

Standalone native run passed 126 assertions covering all click kinds, default and recursive shift behavior, half pickup, place/merge/swap, NBT mismatch, slot rejection/limits, take-only extraction, hotbar rehoming, offhand no-op, creative gating, both supported drag modes and mode-2 rejection in creative/survival, interrupted drag, collect-all, full and single drops, native EMPTY and legacy null removal outputs, base forward/reverse merges and unchanged EMPTY sentinel. This is not live GUI/client/network/server gameplay acceptance or a whole-mod compile.
