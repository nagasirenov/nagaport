# NTM boss display classification, no HUD policy

Run `python3 porting/tests/boss-marker-native/run.py --java-home JAVA8 --classpath NATIVE_CLASSPATH --legacy-client ORIGINAL_CLIENT_JAR`. Uses the actual native engine; no downloads. Windows is untested.

INtmBossDisplay is a genuine NTM domain interface for the seven originally marked NTM entities. Native inherited health/max-health/display-name methods satisfy the contract. The sole original thermal type check uses that marker plus native dragon/wither identities, preserving original vanilla boss classification. It intentionally does not infer display membership from Entity.isNonBoss: that method also controls native portal/dimension behavior, while the old display interface did not. No entity overrides or gameplay rules are introduced.

Eleven focused assertions exercise actual native EntityMob health/max/name inheritance, inherited marker classification, original vanilla boss classes, unchanged Entity.isNonBoss method ownership/result, and rejection of an unrelated mob merely overriding the gameplay predicate. Tests use a marked native mob fixture with no AI and no scoreboard team. Vanilla dragon/wither classification uses actual classes allocated without world startup. This is not full NTM entity compilation, actual portal travel, combat or server proof.

Fourteen existing files change: seven entity declarations/imports, six renderer collector calls/imports (three also casts), and one thermal classifier. Six original BossStatus updates now capture into an NTM-owned state collector. It retains original last-rendered selection, raw health/max division, formatted name, 100 eligible draw lifetime and independent atmosphere pulse. 2,131 additional assertions compare actual original bln/ww bytecode via a separate class loader with native capture, including NaN/infinity, zero/negative health, getter exceptions and partial assignment order. The loader delegates dependency libraries to the native classpath; original engine classes come from the hash-checked original client. Immutable snapshots and future explicit draw/pulse/clear state operations are tested separately, not as active HUD callbacks.

HUD migration, additive coexistence, atmosphere and disconnect cleanup activation remain explicitly pending. No overlay, event, packet, tick or renderer-update consumer is registered. This is real retained domain state, not a replacement UI or a claim that old bars currently work. RenderOverhead itself remains to be ported beyond the classifier. The commented-out SiegeCraft call remains inactive. No fake net.minecraft interface, source exclusion or marker-based gameplay classification is introduced.
