CargoShellCraftingHandler removed container-leave-grid predicate audit
Recorded 2026-10-19 UTC. Read-only audit; this report is the only file written.
CONCLUSION AND SCOPE
For the audited original NTM and original vanilla item families, the Cargo predicate
  item.hasContainerItem(stack) || !item.doesContainerItemLeaveCraftingGrid(stack)
is equivalent to native item.hasContainerItem(stack). Every NTM override that makes
!leaveGrid true also makes hasContainerItem true, including all in-tree subclasses;
vanilla Item returns leaveGrid true and no vanilla Item descendant overrides it.
The two terms are NOT logically equivalent for arbitrary external legacy mods.
An external item may independently return hasContainerItem=false and leaveGrid=false.
Forge2768 has no equivalent item-level leave-grid query. Removal therefore preserves
the verified original NTM + vanilla domain, not arbitrary external legacy-only opt-outs.
No fabricated method, constant compatibility stub, reflection or instanceof policy
is necessary. Original/port ItemFluidIDMulti no-arg hasContainerItem still participates
through the actual virtual stack-sensitive delegation in both Forge versions.
This report does not claim a complete build, runtime startup, or external-mod parity.
