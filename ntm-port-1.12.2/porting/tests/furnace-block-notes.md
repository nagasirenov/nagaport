# Complete electric furnace block native boundary

This is the complete production `MachineElectricFurnace`, not extracted drop bodies. It uses native Material.IRON, BlockPos/IBlockState callbacks, full metadata 0..15, native particles, comparator notification and BlockContainer MODEL rendering. Dedicated JSON models and the client model registrar provide textures, UVs, lighting/culling and item variants; see electric-furnace-model-notes.md. No unused production texture helper remains.

## Behavior preserved

- Legacy `func_149730_j` was the cached opaque-block flag, not dynamic `isOpaqueCube`. The native equivalent is `IBlockState.isFullBlock()`. Official legacy Block bytecode has `j()` return cached field `q`, initialized from `c()` in its constructor; native Block.isFullBlock returns `fullBlock`, initialized from default-state opacity. Tests use opposite cached/dynamic opacity cases, plus all 16 neighbor-solid masks, preserving the original four independent if statements and their order.
- All metadata 0..15 remain representable. The property does not clamp unusual legacy metadata to a horizontal facing. All 4 yaw directions and boundaries, negative/large yaw, custom placement names, active/off item and pick identity remain.
- State swaps deliberately retain the original order: capture metadata/tile, set keepInventory=true, set chosen default block state, set keepInventory=false, restore metadata with flag2, validate and restore the exact original tile. No try/finally repair was introduced. A deliberate fixture exception tests the original sticky keepInventory failure and resets it only inside the test.
- Native Forge modded TileEntity's default shouldRefresh refreshes on every state change. The narrow complete production furnace tile override (owned by the core change) returns oldBlock != newBlock, preserving metadata-only identity. This block probe extracts that exact method into its explicitly controlled NTM tile, not an imitation Minecraft class.
- keepInventory suppresses the explicit inventory-drop and comparator branch. It does not suppress superclass tile removal. Native World.removeTileEntity itself notifies comparators; the fixture counts this separately. Therefore swaps have no drops or explicit furnace comparator call, but still have native superclass-removal notifications. Real destruction emits exact positive-count source drops, then explicit comparator, then superclass removal and its native comparator. This is not described as total-zero comparator traffic.
- Checkpoint17's item/meta/NBT pre-depletion capture, all split bounds, three position floats and per-drop Gaussian order remain byte-identical. No inventory/drop algorithm changes. Null/native EMPTY/zero/negative are native absent slots as already established at the boundary.
- Active particles consume the same two RNG floats even for non-horizontal metadata that emits no particles. Smoke-normal then flame, exact float arithmetic/positions and zero velocities remain. Inactive blocks consume no particle RNG.

## Native probe and honest boundaries

`probe-furnace-block.py` compiles the complete production block and actual RefStrings against the cached native Minecraft/Forge classpath. Controlled NTM collaborators are only ModBlocks identity fields, MainRegistry GUI owner, and a four-slot inventory tile with counters. Its shouldRefresh method is exact extracted production source, printed with SHA256. Native World.setBlockState, Chunk.setBlockState, tile creation/removal, ItemStack, EntityItem and NBT all execute. World observation overrides delegate to native lifecycle; block lighting propagation, entity admission and particle emission are controlled. The 3x3 actual native chunks are fixture-owned, not generated/saved or running a Minecraft server.

The probe covers metadata round-trip and callback types, cached/full versus dynamic opacity, all neighbor masks, placement yaw/name, every metadata's client/server off/on swaps and metadata-only edits, same-object inventory/name survival, exact split drops including rejected spawns, comparator/removal order, particle RNG/positions, activation's client/sneak/missing-tile paths, and original keepInventory exceptional behavior. Positive GUI opening is not executed. This probe does not compile the complete actual furnace tile, run its tick, or establish combined tile/block/network/GUI acceptance; a separately named combined probe may establish a narrower combined boundary. It does not establish live client/server/chunk reload/world-save/render/GL acceptance.

## Known deferred visual gate: generic debris

The completed smoke/flame callback and six-face cube/UV tests do not establish all original particle behavior. Original Forge 1.7.10 patched EntityDiggingFX to select `world.rand.nextInt(6)` and use that face's legacy icon. That affects hit/destruction debris and the reachable blockcrack/running and blockdust paths. Native ParticleDigging instead consumes the model's fixed particle sprite. The current dedicated model keeps its documented fixed particle fallback, so random-face debris parity is NOT achieved.

A narrow replacement is not just a texture swap: native ParticleManager owns a private hit-position RNG, and native Block.addDestroyEffects no longer receives the old destroyed metadata argument, although the manager still receives a supplied state. Replacing RNG streams, guessing destroyed metadata, adding a partial hit/destroy-only fix, or replacing global particle factories would not establish full source parity. Those changes were intentionally not made. The parent bounded this checkpoint to the functional machine batch and the achieved block lifecycle, six-face geometry/UVs and active smoke/flame behavior. Full visual/game acceptance remains open. Evidence: official Forge 1.7.10 EntityDiggingFX/EffectRenderer patches and native ParticleDigging/ParticleManager bytecode; no claims depend on temporary evidence files being packaged.
