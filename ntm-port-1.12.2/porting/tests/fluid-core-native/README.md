# Shared fluid core native regression

Complete production owners: FluidTank, FluidLoaderStandard/FillableItem/Infinite, FluidContainerRegistry, IFluidStandardReceiver/Sender, IFluidPipeMK2, IFluidReceiverMK2 and IFluidStandardSenderMK2. Seventeen unchanged production sources include the actual two-pass receiver/provider algorithms, ILoadedTile cache, FluidNode, tuples and coordinate/direction classes.

Run with Java8 and the native Forge/MCP dependency classpath:

    python3 porting/tests/fluid-core-native/check-mapping.py --source-root .
    python3 porting/tests/fluid-core-native/run.py --module . --source-root . --java-home /path/java8 --classpath "DEPENDENCY_CLASSPATH"

`source-map.json` pins complete input sources at CP40 c97cd8bb2646b39e3688922121b7af888c130aa8 and resulting hashes; `check-mapping.py` reconstructs all ten whole-file transformations exactly, with no broad regex on unrelated files. Production continues accepting historical null slots, while native EMPTY is also treated as absent; consumed output slots use EMPTY. Registry methods deliberately retain their historical null-return contract. No changes to amounts, pressure rules, mutation order, two-pass distribution, names, recipe/container registration order or NBT/wire format.

2,300 native core assertions cover capacity/debit/receipt, native ItemStack identity/count/name/remaining NBT, full/blocked output, no-return-container ores, missing inputs, identifier whole-stack movement, pressure/type filtering, fillable items and armor callback asymmetry, infinite handlers and seeded chance, signed/truncated pressure, NBT legacy names and missing/negative max quirks, exact 14-byte ByteBuf, large/overflow/negative two-pass values, direct actual World tile lookup with both speed caps, cached tile invalidation, six neighbor subscription order and native tile node coordinates. Pure renderer formula tests add 5,347 assertions across native BufferBuilder contents and exact intended tint/bind/blend/postcondition order. Only six GPU/engine-holder calls in the compiled FluidTank render method are redirected to captures by the explicit ASM harness; the native buffer and production method body run. This is NOT a live GL visual/state-cache test.

Nineteen explicit external NTM collaborators in run.py are fixtures: FluidType/Fluids definitions; GUI tooltip helper; BobMathUtil; ArmorModHandler; ItemInfiniteFluid; ModItems/ModBlocks registries; GeneralConfig; SolarSystem; Compat lookup adapter; INetworkProvider/GenNode/UniNodespace/FluidNetMK2 topology; energy priority enum owner; packet dispatcher/particle packet; Library direction constants. No Minecraft or Forge class is replaced. The real custom FluidContainerRegistry is compiled and exercised with registered test containers, not a substitute registry. Its complete default content-registration method compiles and is exact-mapped, but actual global ModItems/Fluids initialization and compatibility registration are not run. Infinite item's environment/orbit behavior and armor storage implementation are not certified by callback fixtures.

Native Forge item registration is used, not the locked vanilla Item.REGISTRY wrapper. Bootstrap warns about no active mod container for fixture namespaces; this is visible, not suppressed. No launched client/server, complete topology lifecycle/unload/reload, entire fluid catalog, full machine/teleporter, cross-mod integration or Windows acceptance is claimed. Do not infer whole-mod success from this harness or its assertion count.

Final native EMPTY returned-container review: an EMPTY registry container is normalized to the existing null-result contract. Regression checks verify a named consumed ore cannot attach a name to the shared ItemStack.EMPTY sentinel. Final frozen full compile was repeated after this correction.
