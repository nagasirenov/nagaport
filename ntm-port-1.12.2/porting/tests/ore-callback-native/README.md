# Native BlockOre callbacks (incremental after CT palette)

Baseline: 7838e7f5fe4e1294e14e434d778f9211267bb9ce. Production changes only BlockOre. No registry, resource, model, rarity policy, fortune formula, scalar drop algorithm, or subclass source changes.

Four real native overrides dispatch to the existing NTM-owned scalar hooks: item drop, drop damage, creative variants, and placed-by. Keeping those hooks is necessary: actual BlockCluster overrides the scalar item hook, and BlockOre's fortune algorithm dynamically calls it. These are domain methods on this NTM owner, not fabricated methods on Minecraft Block/World. The three rarity constants only adopt native enum spelling. Native creative callback retains SideOnly(CLIENT).

The existing scalar placement operation becomes an owner-local native state operation with the same stack read, null check, bounds and flags2. Special care: original Chunk compares raw metadata before its storage truncates to four bits. Equal native state with unequal raw damage must still dirty the existing section and notify a populated chunk. The tests execute the original client jar's Chunk and ExtendedBlockStorage methods directly, alongside real native World/Chunk. No old World facade is added. Native setBlockState governs actual native lifecycle; this is not certification of arbitrary foreign blocks, special debug worlds, lighting, or all old-world internals.

Run from module root:

    python3 porting/tests/ore-callback-native/source-proof.py
    python3 porting/tests/ore-callback-native/run.py --java-home /path/to/java8 --classpath-file /path/to/native-classpath.txt --legacy-client /path/to/original-client.jar --mutants

The native test compiles complete production BlockOre, BlockCluster, interfaces and MultipassContext. NTM collaborators are explicit bounded fixtures: identity slots for 22 drop predicates, real native Items, a creative tab, two config fields, and localization keys. The complete actual Body and EnumChunkType enum bodies are extracted; unexercised astronomy methods fail closed. Titanium uses its exact production constructor. Other predicate instances are intentionally not claimed to reproduce their full registry constructors. This exercises shared callback predicate behavior, not full ore-family game initialization.

The original scalar item/damage/quantity algorithms are extracted byte-for-byte from the archived baseline, with only the counterpart identity-table qualifier changed. Test grids cover 16 states, both fortune switches, five fortune values including negative, twenty seeds, native Block.getDrops RNG, all four actual BlockCluster overrides, creative order/identity, scalar-hook virtual dispatch, rarity, raw-int placement boundaries, null world, actual ItemBlock.placeBlockAt, and World.destroyBlock spawning actual EntityItem stacks. Raw ItemStack damage is injected reflectively because ItemStack is final; getter order/count is separately asserted from exact source, not falsely instrumented at runtime. World lighting calculation is explicitly bypassed in the fixture. Registry, World, Chunk, Block state, items and drops are genuine native classes.

All three direct descendants were audited: BlockCluster, BlockOreFluid, BlockOreOutgas. Only Cluster overrides one of these four scalar hooks. Fluid and Outgas inherit them unchanged, but their own unrelated fluid/outgassing/tick/entity callbacks remain unported, and these tests do not certify those classes' full behavior. `callers.log` records the entire tracked-source dotted callback search. The only BlockOre-internal scalar call is the preserved fortune hook. Generic Block-typed legacy calls (including ModBlocks' generic helper and BlockRemap) remain pre-existing unresolved roots, not silently repaired or claimed compiled here. Existing native falling-block/wand callers now dispatch the proper owner overrides. No caller signature was removed.

Existing multipass/CT visual gates remain unchanged. No pixel acceptance, full-generator, complete mod compilation, or launched-game claim. This callback root enables a subsequent separately audited titanium placement batch; it does not itself migrate those placements.
