# Remaining native item callback family

## Production boundary

Eleven complete original callbacks now use the existing native typed model/RenderItem ownership transaction: MeteorSword, Hot, Missile, MissilePart, BigSword, RedstoneSword, GunAnim/B92, Shim, Gavel, Chainsaw and Crucible. GUI selection and declined full-base-model overrides/perspectives remain explicit. No removed Forge interface, Object-array protocol, fake platform classes, source exclusion or invented mesh was introduced. `native-remaining-items-production-scope.json` enumerates the exact production bytes and retired paths; the evidence manifest enumerates the runnable checks and final logs.

The seven weapon and two missile callbacks retain the complete original ordered transforms and draw bodies, actual original Java models/OBJ/HFR/VBOs, materials, parts, colors, clocks and animations. Nine pristine-source body oracles are compiled without unpublished Git objects and compared at real model draws. Native left hand uses the existing Forge mirror. Newly supported HEAD/NONE use the approved centered original entity mesh. Full-3D tools retain their original separate equipped caller, blocking and rotate-around branches; ordinary items retain the ordinary caller.

Original entity helpers remain per-family: BigSword/RedstoneSword/B92/missiles have no bob or spin; Shim/Gavel/Chainsaw/Crucible retain both. All draw one complete mesh regardless of command-created oversized stack counts. Direct drop and machine-frame draws restore native rescale-normal state and lightmap state. Fixed item frames retain the existing approved pivot correction, with the correct original zero-bob versus .1-bob distinction. Invalid/hidden/model-less parts decline to the genuine vanilla path, including native copy-count/spread behavior, instead of becoming invisible. The optional `handlesDropped` method defaults to true for every existing block-item delegate.

Hot retains its five exact original heat-overlay PNGs and original alpha ratio. Its complete ItemHot owner uses native NBT access, preserving static maximum-heat behavior, server-only decrement, zero-tag lifetime and next-tick tag removal. No heat balancing change. Meteor swords retain their eleven colors, always-on HBM shimmer even without enchantment, ordinary entity/frame fallback and exact original dimensions. The three Java-weapon PNGs are renamed lowercase byte-for-byte; no resource pack model or material is replaced.

HbmAnimations is compiled as a complete native class. The new explicit-holder overload reads the existing rail only for the actual local selected main-hand stack. Offhand/remote/absent holders never borrow another item's animation. This does not invent offhand animation rails. Crucible equip snapping addresses the selected real native hand, checks the exact native ItemRenderer owner, preserves the pre-snap values used by the original blade test, and leaves the other hand/unknown renderer untouched. B92 pump offsets unwind on model failure as well as normal completion.

The shared native GL cache synchronization now includes all eight light enables and color-material enable/face/mode. This repairs a verified real-native issue where glPopAttrib restored disabled GPU lights while RenderHelper's Java cache still said enabled; the next helper enable otherwise silently did nothing. Hot and Meteor normal/failure tests prove the subsequent native helper changes actual GPU state. A nested GL_LIGHTING_BIT transaction also preserves both faces' ambient/diffuse/specular/emission material vectors while the cache is repaired: enabling color material, changing its face/mode and reissuing current color can otherwise overwrite those vectors after the original attrib pop. The final gate covers all 30 enabled/disabled × face × mode combinations and normal/failed Hot/Meteor callbacks, including unchanged current color, balanced attrib depth and the subsequent actual native helper transition. Raw light/material parameters are not cached by GlStateManager and are restored by the lighting attribute scopes.

ClientProxy owns integration. Its original 30 hot/sword/weapon registrations now enter the deferred typed map. MissilePart.registerAllParts is called exactly once before model registration through a guarded client helper; the existing later post-initialization entry calls that same guard. The complete missile part table only depends on registered item identities, original ResourceManager fields and a RenderDropPod constructor. No recipe or world dependency is moved. Captured part identities survive the later post-load call. Server part registration remains unchanged. Dropped delegates activate only after the existing exact-owner transaction succeeds.

The unregistered `ItemRenderWeaponMiniFEL` source was retired after full source-tree reference audit found no caller/registration. The original itself had an empty draw and unmatched matrix push. No missing FEL geometry or gameplay was invented; no reachable item registration was removed.

## Explicit limits

This is genuine native headless EGL evidence, not a launched client or visual acceptance, full-mod compile success, gameplay acceptance, network/save migration, electricity or radiation acceptance. Test-only NTM data holders replace ModItems/ResourceManager field ownership, configuration speed and recipe fixtures; ResourceManager initializer expressions and all selected actual original meshes/materials are retained. The complete production MissilePart/MissileMultipart and MissileStruct are compiled. MissilePronter's original `prontMissile` method and GunB92's original animation/NBT methods are extracted with native API spelling; the larger rocket renderer/gameplay owners are not certified. ItemToolAbilityFueled's fuel decision is controlled data to test both original draw branches, not fuel-mechanics acceptance. RenderDropPod construction is an explicit metadata collaborator, not drop-pod gameplay acceptance. A real native Player/World type holder is allocated without a world startup for bounded callback tests. Original-versus-native in-game hand motion, lighting, equip progression, frame placement, reload and cross-mod runtime tests remain necessary after the mod compiles.
