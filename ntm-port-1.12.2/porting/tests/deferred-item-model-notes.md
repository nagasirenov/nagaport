# Registry lifecycle and dedicated-server correction after checkpoint 26

Checkpoint 26's renderer probes started with already registered fixture items. They did not test `MainRegistry.PreLoad` -> the complete production `GameRegistry` queued Block/Item events -> native `ModelRegistryEvent`. Production model initialization ran too early: `Item.getItemFromBlock` could return AIR and the provider item enumeration omitted queued armor items. This also affected the earlier static ItemBlock family.

`ClientProxy.registerItemRenderer` now installs only a public deferred event subscriber. The first real model event initializes static/callback/direct item ownership after actual registry flush. Each newly created model subscriber explicitly handles the current event before subscription, because an in-flight event is not replayed. Initialization is guarded before callback entry against reentry. Initialization exceptions propagate; a partially failed setup is never silently retried.

`probe-deferred-item-registry.py` compiles complete production GameRegistry, RefStrings, ItemRenderBase, IItemRendererProvider and DeferredItemModelRegistration against native Forge. Genuine transformed event classes and Forge registries demonstrate queued ItemBlock construction, pre-flush AIR/missing providers, actual block/item flush, correct identities, explicit in-flight model registration and repeat/reentry/failure behavior: 32 assertions. The final model callback is controlled, not the full ClientProxy, model bake or game.

The native renderer return type also crosses a common-side interface. Method-level `@SideOnly(CLIENT)` now strips only `getRenderer` from that interface and 15 common armor implementations. Common item lookup methods and all factory bodies remain unchanged. `probe-item-provider-side.py` checks exact annotation-only source reversals for all 16 files and uses genuine Forge SideTransformer on the complete compiled interface. The negative control without annotation fails reflective method resolution under an explicitly client-denying loader; the corrected server interface retains both common methods, and client transformation retains all three. Seven native checks pass. This is not a whole armor compilation or dedicated-server launch.

Commands: `python3 porting/tests/probe-deferred-item-registry.py --java-home PATH_TO_JDK8 --classpath NATIVE_CLASSPATH` and equivalently `probe-item-provider-side.py`. No replacement Minecraft/Forge API classes. Existing checkpoint 26 does not contain these corrections; apply the subsequent checkpoint before treating this lifecycle as fixed. Full client/server launch remains blocked by other port compilation errors.
