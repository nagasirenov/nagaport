# Spawn-item native callbacks

Complete ItemChopper compiles against actual Forge1.12.2/MCP stable39. Run `python3 porting/tests/chopper-native/run.py --java-home JAVA8 --classpath NATIVE_CLASSPATH`. No downloads. Windows run is untested.

3,586 assertions cover all five original item identities, all six faces, both native hands, creative/survival, ordinary, oak-fence, nether-brick-fence and actual NTM metal-fence supports, original species height offsets, UFO cooldown, one initial-spawn callback, yaw/head/render agreement, item naming and original consumption even when the world rejects a spawn attempt. Liquid right-click covers misses, entity hits, edit/mine refusal, nonliquids, named liquid spawns, reach and native ray flags. Client callbacks never spawn/trace/consume. Unknown item identity remains inert; tooltip lines unchanged.

Test boundaries: the five mob classes are explicit EntityLiving-derived recording collaborators, not certified combat/AI implementations. A real World subclass records world side effects and permission/ray results; player equipment audio is suppressed. This proves the complete item callbacks against native entities/items/player APIs, not complete mob spawning, live multiplayer, combat or game integration.

Original source uses Item.getMovingObjectPositionFromPlayer(world,player,true), not the intermediate port's invalid three-argument player.rayTrace. Native Item.rayTrace restores that API boundary. Forge1.7.10 Item.java.patch sets the server ray distance from EntityPlayerMP.theItemInWorldManager.getBlockReachDistance, native Forge1.12 uses EntityPlayer.REACH_DISTANCE; both retain eye-height origin and flags true,false,false. The test uses configured reach7 and validates the actual native ray endpoint. No hardcoded reach5 regression.

CP49 corrects the local, withheld CP48 predicate: original render-type11 fence offset becomes BlockFence excluding BlockMetalFence. Original BlockMetalFence extends BlockFence but overrides getRenderType with its custom renderID, so it must not receive the extra half block. The complete native BlockMetalFence and IBlockMulti compile in this test; only ModBlocks.fence_gate is a domain collaborator. The expected offset uses independent identity checks for the two vanilla supports, not the production predicate. A search of all pristine original Java sources found BlockMetalFence as the sole NTM BlockFence subclass and no subclasses of BlockMetalFence. Unknown external subclasses remain outside the scoped original audit. Other mods' obsolete arbitrary render-type11 assignment is not a supported native API or certified here. Native SUCCESS on an actual liquid spawn prevents invoking another hand after a successful spawn; misses/refusals return PASS without consumption. onItemUse retains original always-handled result, including client and unknown item identity. Native spawn initialization receives the position difficulty as required by 1.12; mob-specific callback internals remain outside this slice.

No changes to species choice, original offsets, count formula, cooldown, permission conditions or naming order. MainRegistry activation and boss HUD are untouched.

Negative control: in a disposable source copy, removing only ` && !(block instanceof BlockMetalFence)` restores the CP48 predicate. The same whole-class native suite fails at `original face/fence/species offsets`. Main production remains corrected.
