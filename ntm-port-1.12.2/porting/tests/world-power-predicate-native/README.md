# CP70 native boolean power predicate family

Base: `ea933e28fe3a1a9a60e9d438411a02182b2ab22a` (CP70). Production scope: 58 call expressions in 47 existing files. No added production adapter, changed callback signature, rewritten body, integer-power aggregate, lighting rule, gameplay balance, dependency or source exclusion.

Each selected expression changes only `receiver.isBlockIndirectlyGettingPowered(x, y, z)` to `receiver.isBlockPowered(new net.minecraft.util.math.BlockPos(x, y, z))`. Receiver spelling and the complete original argument text are preserved. Receiver evaluation remains before the three left-to-right argument evaluations, exactly once each; local custom positions are not collapsed to native tile position fields. Native BlockPos construction necessarily introduces allocation and its potential VM allocation failure; equivalence does not claim identical out-of-memory behavior.

## Receiver and source proof

The Java 8 compiler parser inventories all project Java sources, with class/nested/anonymous ownership, field ancestry, lexical parameter/local/lambda/loop scopes, and source positions. This is parse/scope attribution, NOT whole-project javac type attribution or compilation. All 58 selected expressions are positively resolved: 31 explicit native World parameters/locals and 27 unshadowed inherited native TileEntity.world fields. Native field declarations and boolean signature are checked against the actual classpath. No project declarations of either power method or classes shadowing World exist. The only textual old call remaining is an existing commented-out worldObj call in CraneUnboxer, left byte-identical. Inventory controls reject custom receiver types and shadow fields, and verify nested anonymous ownership and comments/string exclusion.

`selection.json` records every original and replacement expression, original enclosing method or lambda, lexical bindings, owner chain, source spans and prior engine proof hashes. `baseline.zip` contains 53 exact CP70 files: the 47 selected files plus six ancestry collaborators. `source-proof.py` verifies every output byte and exact inverse against these preimages; it also independently inventories the migrated tree. Three edited lines retain original CRLF. Use `git -c core.whitespace=cr-at-eol diff --check`; do not normalize original line endings.

## Reused engine proof

The unchanged sibling `block-neighbor-native/dispatch` package is hash-pinned in selection.json, rather than duplicating or rerunning the previous engine audit. Its actual legacy vanilla and native Forge bytecode CFG comparison established the boolean mapping, six-face order and short circuit for 729 sign partitions, and separately checked 729 integer-aggregation partitions. Native isBlockPowered is boolean; native getRedstonePowerFromNeighbors is the different integer aggregate. The prior proof explicitly limits modded leaf power equivalence: native Forge shouldCheckWeakPower defaults to normal-cube behavior, but arbitrary external redstone circuits are not proven identical.

## Native runtime evidence

`run.py` compiles and runs all 58 exact selected expressions with real World, TileEntity and BlockPos types, plus seven complete selected methods and the complete REDSTONE lambda. Complete methods are the two battery mode/cache methods, dipole checkRedstone, mining-laser multiblock power check, generic-door updateRedstonePower, chlorine-seal update, and blast-door update. The production custom BlockPos, DirPos, Rotation, ForgeDirection and Spaghetti files compile unchanged.

PASS: 2,518 assertions; four runtime mutants rejected; old scalar World compiler mutant rejected. Actual generated bytecode has 67 boolean native World invocations (58 expression fixtures plus nine calls in the seven methods/lambda), not a fake old World API. Real World/Chunk and vanilla redstone blocks execute for all 58 expressions, both remote flags, no power and each of six powered faces. Assertions check exact receiver, coordinate values, once-only calls, native face order and short circuit. Methods exercise cache bypass, local-position shadowing, mutable custom positions, loop early returns, computed opposite-side positions, edge-count/sentinel preservation, server gates, locked upper blast-door power precedence, and repeated-power no-double-toggle behavior. Getter side effects establish receiver capture before coordinate evaluation and separate this.pos field reads; getter/null-receiver/World exceptions retain order and no retry. Four signed-int boundary cases capture arguments at the native World entry before throwing a declared marker, so these validate integer construction/overflow, not actual far-away world/chunk queries.

Owner shells retain only required fields and explicit NTM domain boundaries. Chlorine spreading, blast-door toggling/packets/animation, and port suppliers are recording fixtures, not claimed production gameplay. The complete blast-door method compiles, but animation state 1 is deliberately not exercised. No vanilla/Forge classes are stubbed. Complete owners, full mod compilation, explosions, actual network serialization, GUI/client rendering, live-server tile scheduling, and arbitrary external World subclasses are NOT accepted by this probe. The actual ITickable callback is invoked, not the full World scheduler. Parent checkpoint policy holds remain in force.

## Reproduce

```sh
python3 source-proof.py --java-home /path/to/java8 --report attribution.json
python3 run.py --java-home /path/to/java8 --classpath-file /path/to/native-classpath.txt --mutants
```

`native-test.log`, `native-attribution.log` and `native-api-receipt.json` record the successful run. The first fixture extraction attempt incorrectly matched an earlier getRelevantMode caller; extraction signatures were corrected to complete declarations before the successful compile/runtime runs. This was evidence-generator only; production did not change.

`apply-fragments.py --module /path/to/ntm-port-1.12.2` performs a dry-run against collaborator edits; append `--write` only for authorized integration. It preflights exact counts and verifies a selective inverse before writing, preserving every other byte. `main-fragment-dry-run.json` records a successful 58-call dry-run, not a main edit. Whole-file strict proof remains scoped to the isolated exact CP70 tree, while fragment inverse proof composes with unrelated changes.
