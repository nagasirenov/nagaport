# Audited vanilla stone-brick placement boundary

Exact baseline f31798aac92b494bf4ee3123112a765e5f283e8a, following the separate fence batch. The coordinator's CP61 already contains that chain; no rebase or main edits were performed.

415 production placements: 414 in LibraryDungeon and one in EntityChemical. The dungeon retains its exact public virtual getBrick(Random) body (rand.nextInt(3)) and each call at the original argument position. A private, static, owner-local helper accepts actual BlockStoneBrick, coordinates and the already evaluated metadata; it preserves receiver capture, coordinate/owner/metadata order, null timing, original bounds and flags3, then dispatches genuine World.setBlockState. The immutable Blocks.STONEBRICK value is evaluated and cast before getBrick, exactly where the original owner argument was read. Actual original/native owner identity proves the cast cannot fail in scope. The helper accepts neither arbitrary Block nor arbitrary flags and is not a generic legacy World API. The chemical metadata1 call uses direct native captured locals. Existing DungeonToolbox/placeRandomConcrete and all models/resources are untouched.

All 4,050 tracked sources were scanned for LibraryDungeon descendants/anonymous subclasses, Random descendants and writes to Blocks.STONEBRICK; none were found. The actual caller constructs LibraryDungeon directly. Native Java8 attribution proves the immutable vanilla field and actual getBrick method owner, as well as int arguments, World receiver and standalone statement. The complete real EntityThrowableNT ancestor is provided to attribution so EntityChemical's inherited Entity.world is resolved rather than guessed. Twelve ownership controls and four closure mutations pass. Source reconstruction and complete inverses prove all remaining code and the selector body unchanged.

The scoped selector range is 0..2 under java.util.Random.nextInt's contract; metadata3 is additionally proved as a genuine native stone-brick state and exercised by a virtual override test. There is no clamping, whitelist rejection or new fail-fast branch in production. Arbitrary external LibraryDungeon/Random overrides producing unsupported metadata, reflective replacement of the final singleton, and third-party legacy World overrides are outside this closed-source proof. Native World virtual dispatch is retained and tested by an overriding recording World; the owned FauxWorld does not override the old six-argument placement method. Unrelated FauxWorld port errors are not certified fixed.

The native owner test loads the actual original client BlockStoneBrick (anw), registries and Item implementation in an isolated classloader and compares real owner identity/ID, metadata0..3 drop damage, item identity, quantities and RNG continuation against actual native Blocks.STONEBRICK. Actual native World/Chunk placement, global state IDs, no-tile lifecycle, Block.getDrops, compressed Anvil save/load and World.destroyBlock/EntityItem drops preserve all four variants. Native state invalid metadata behavior is not used as an oracle for unsupported old raw metadata.

Selected-expression original/native stream tests cover 12 seeds, nine origins including overflow/bounds, null receivers after selector draws, effectful receiver/coordinates/owner/virtual metadata dispatch, exceptions at all six evaluation positions and RNG continuation. The actual original World bounds bytecode prefix is executed. Six runtime helper mutations reject null/bounds changes, metadata0 normalization, flags2 and dropped placement. 878 total owner/placement checks and 18,288 exact events pass, including 321 real original/native owner checks. World lighting is explicitly bypassed in the real-World fixture; no lighting or visual acceptance is added.

Actual unsplit selected-expression Code sizes are 107 bytes for the chemical call and 16,650 bytes for all 414 dungeon calls through the private helper. The measured direct expansion of those same 414 expressions compiles to 49,770 bytes; it does NOT itself exceed the JVM limit. No standalone size rejection is claimed. The helper avoids that large expansion inside the already large, still partly unported generator. These numbers concern complete selected sequences, not a successfully compiled full LibraryDungeon or launched generator. Existing unrelated WorldGenerator signatures, shelves and other native port work remain separate. No full mod compile was run by this worker.
