## Paired expressions and conversion proof

`generate-fixtures.py` uses identical complete receiver and argument expressions on both sides. Only the engine type, dispatch target and callback adapter differ. Both nested/member receivers and nested getter receivers are compiled. Argument expressions contain nested method/member evaluation, not precalculated converted values.

`verify-bytecode.py` compares every pre-invocation instruction, normalizing only fixture names, engine World descriptors and constant-pool indexes. All 12 paired wrappers match. The two migration shapes contain respectively three and one `i2d` opcodes, and preserve the already-float volume/pitch loads. Separate robustness shapes exercise `l2d`, `f2d`, `i2f` and `l2f`; the existing all-double shape is also a regression control.

The runtime compares raw double/float callback bits, including signed zero, integer extrema, values around 2^24 and 2^53, float/double subnormals, infinities, NaNs and deterministic random bit patterns. Independent checks establish that int 16777217 reaches the callback as exact double 16777217, while robustness-only long 9007199254740993 rounds to double 9007199254740992 and int 16777217 rounds to float 16777216.

Null World receivers evaluate all argument expressions before failing. Null intermediate receivers fail before arguments. Scripted exceptions at each receiver/argument stage preserve ordering and precedence, including an argument failure winning over a null final World. Each executed callback occurs once. Four actual compiler-negative controls reject double-to-float narrowing and Object receivers in both original/native forms.

## Explicit limits and name caveat

Original custom listeners receive the raw String. Native custom listeners receive a SoundEvent whose ResourceLocation normalizes its path to lowercase. The tests deliberately record this pre-existing representation difference: 5,652 successful callbacks use mixed-case names that differ as raw strings. They assert the exact original name and the correctly normalized native name separately, not raw-string identity. The ordinary registered/native resource playback behavior remains covered by the unchanged regression tests. No arbitrary foreign name was added to the allowlist.

These tests establish numeric invocation conversion/evaluation behavior and the existing bounded bridge behavior. They do not certify all production methods compile, launch a game, verify audible output, or resolve dormant entity-player coordinate semantics. Client/world startup and audio hardware remain controlled boundaries, as in the existing proofs.
