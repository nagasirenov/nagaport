# Native AxisAlignedBB factories: literal-only ordered geometry

Baseline: CP53 `5663b44d12fe9cad50d7d1a10496e55d32eabc9d`. This is a deliberately bounded subset: 74 factory expressions in 14 production files. Only the factory selector changes to `new AxisAlignedBB`; all six argument expressions are byte-identical. No dynamic factory is changed, no compatibility layer, reflection, field mutation, stub or runtime guard is introduced.

## Why a global rename is incorrect

Original 1.7.10 `azt.a(DDDDDD)Lazt;` (`func_72330_a`, mapped by joined.srg from the supplied SRG archive) creates a box whose constructor directly stores six doubles. Native 1.12.2 `AxisAlignedBB(DDDDDD)V` uses Math.min/Math.max to sort each coordinate pair. Inverted pairs, a NaN on only one endpoint, reversed infinities and +0.0/-0.0 ordering can therefore change. Tests explicitly require those differences; they do not silently normalize or fail fast in production. The javap evidence records actual classes, not reconstructions.

Every accepted expression has six numeric, literal-only arithmetic arguments. Javac proves receiver is the native TypeElement, rejecting shadowed/domain/instance receivers and nonnumeric/unresolved arguments. The actual Java oracle evaluates every exact expression, proves all endpoints finite and ordered, and compares all six raw IEEE754 bits. Numeric overload conversion is therefore the original six-double conversion; final attribution verifies the actual native six-double constructor. Static factory and new-expression operand order is exercised; selected operands have no effects or dynamic reads, so no argument side-effect or class-initialization-order dependency is introduced.
